# 校园服务平台 · Campus Service Platform

面向西南大学在校学生的校园服务微信小程序，把校园二手交易、代取跑腿和站内沟通集中到一个入口，让「卖东西」「找人帮忙取件」这两件小事在校园内更快闭环。本项目为《数据库原理与应用》课程设计作品。

## 为什么做这个项目

校园里的二手交易和代取需求并不少，但几乎都发生在校园频道帖子和群里，问题集中在五处：

- **渠道分散**：看中一件东西要反复加好友、私聊，沟通成本远高于商品本身的价值。
- **信息易沉底**：帖子很快被新内容覆盖，群消息更是刷屏即消失，供需双方都找不到对方。
- **状态不透明**：物品是否售出、订单是否完成更新不及时，大量咨询最终是无效沟通。
- **检索能力弱**：只能靠翻记录找东西；二手书更麻烦，同一本书有版本、出版社、ISBN 的差别，反复核对才能确认是不是自己要的那本。
- **代取无入口**：需求方不知道谁愿意顺路帮忙，愿意跑腿的同学也接不到稳定的单。

## 核心功能

### 二手交易

- **发现**：首页分类浏览，支持关键词搜索、价格与时间排序；书籍类商品在搜索结果中以书目卡片聚合，同一本书的多个在售商品优先展示。
- **详情**：图片轮播、价格与原价、成色、议价标记、卖家信息与信用分、收藏数，可一键收藏或联系卖家；卖家本人还能在详情页直接管理商品状态。
- **发布**：普通商品填写标题、描述、价格、成色、是否可议价即可发布；书籍模式先从书目库按书名 / ISBN 联想填充作者、出版社、版次，避免重复录入。
- **管理**：我的发布或商品详情页中可在「在售 / 已预订 / 已售 / 已下架」之间切换状态；和买家谈好后可标记预订，商品自动从首页和搜索中隐藏，谈崩了取消预订即恢复在售，重新上架也无需重发。

### 代取服务

- **发单**：先选片区、再选该片区下的具体地标（也可以只选片区），填写物品规格、报酬与时间要求（尽快 / 截止时间 / 时间范围）发布订单；取件详细地址与交付要求写在备注里，备注框有灰色提示引导；可先浏览可接单跑腿直接联系，没有合适人选再转入代取大厅公开招募。
- **接单**：跑腿同学可多选服务片区和更细的具体地标（地标可留空表示整个片区都接）、设置按具体日期或按星期循环的在线计划、能承接的物品种类（小件 / 中件 / 大件可多选）与基础报价；到计划时间自动上线 / 下线，也可随时手动“现在上线”或提前下线；上线后在大厅自主选单，接单后订单锁单并从大厅消失；发布者可撤回接单、接单者可释放接单，订单退回大厅。
- **订单管理**：我的代取区分「我发布的」与「我接的」，状态变更实时可见；截止时间仅作参考，系统不因超时自动取消。

### 站内沟通

- 会话列表展示最后一条消息与未读数，支持文字与图片消息即时沟通。
- 会话与商品、代取订单绑定：从商品详情或订单详情发起沟通，双方一进来就知道在谈哪件事，不必先互加好友。
- 聊天页顶部固定本次沟通的商品 / 订单卡片，展示标题、价格或报酬与当前状态，点击可回到详情。卖家在商品详情页、发布者 / 接单者在代取详情页按角色管理状态，买家 / 对方只读；返回聊天页后卡片状态同步更新。

### 个人中心

个人资料、我的发布、我的收藏、我的代取、接单设置、帮助反馈集中在一处。

## 项目优势

**1. 只做校园，场景边界清晰**

平台不追求大而全，只覆盖校内二手与代取两件高频事。用户以学号注册，交易建立在同一校园的身份信任之上，不需要额外的实名体系就能降低一部分风险；地点采用「片区 + 具体地标」两级：片区用于匹配，具体地标用于精确到楼栋，比通用二手平台更贴近实际使用。

**2. 二手书是专门优化过的品类**

书是校园二手交易里占比最高、也最难描述的东西。平台把书目信息（书名、作者、出版社、版次、ISBN）从商品中独立出来做成书目库：发布时联想填充，浏览时同一本书的多个卖家聚在一起比价，买家不用再逐条核对版本和出版社。这是通用二手平台不会为校园场景做的细节。

**3. 信息不沉底，找得到也筛得准**

二手有独立的结果页而不是无限下拉的首页流，关键词、分类、价格区间、发布时间可以叠加筛选，搜索结果按书目聚合、同书商品优先。商品状态（在售 / 已预订 / 已售 / 已下架）始终展示在列表和详情上，看到的就是当前真实状态，减少「问了才知道卖了」的来回。

**4. 代取做的是双边撮合，不是一张公告板**

- 供给端可以声明服务片区和具体地标（均可多选，地标留空表示整个片区都接）、按具体日期或星期循环的在线计划、可接规格与报价；计划到点自动上下线，也能手动覆盖，避免接单期间被打扰；
- 需求端可以先找可接单跑腿直接联系，匹配不到再转公开大厅，两条路径覆盖「急」和「省」两种诉求；
- 接单使用事务加行锁，两个人同时点一单只会有一个成功，不会出现重复接单后再互相扯皮。

**5. 聊天带着业务上下文**

会话与商品、订单绑定，消息列表能直接看出这次沟通是关于哪件商品或哪张订单；聊天页顶部的业务卡片把这条上下文固定在眼前，点回去就能看详情、改状态，聊完再回来也不会失去上下文。订单相关的沟通围绕完成、取消等履约情况展开，沟通和履约状态不会脱节。相比在微信里加好友再对暗号，路径短得多。

**6. 数据设计扎实，状态有据可查**

14 张表按业务主线拆分，满足 3NF；书目、商品图片、跑腿设置、状态日志各自独立，避免一条记录里塞进所有信息。商品与代取订单的每一次状态变化都会写入日志表，谁在什么时候改了什么可以追溯。列表页需要的收藏数、会话列表需要的最后一条消息作为有意保留的冗余字段，由触发器自动维护，读多写少的场景下既快又不容易错。金额统一用精确小数类型，不用担心浮点误差。

**7. 轻量，开箱即用**

客户端是无需构建的原生小程序，后端只依赖 Node 与 MySQL，图片存在本地磁盘。这套选型让系统可以在普通笔记本上完整跑起来并演示，不需要云服务、域名或备案；对校内小规模使用来说，部署和维护成本几乎为零。

## 技术架构

| 层次 | 选型 |
| --- | --- |
| 客户端 | 微信小程序（原生 WXML / WXSS / JS） |
| 服务端 | Node.js + Express，`mysql2` 连接池，参数化 SQL；`node-cron` 每分钟维护跑腿在线计划 |
| 数据库 | MySQL 8.0（InnoDB / `utf8mb4`） |
| 鉴权 | JWT + bcrypt 密码哈希 |

## 数据库设计

14 张表分四条主线：

| 主线 | 表 | 承担的业务 |
| --- | --- | --- |
| 用户与二手 | `users`、`books`、`categories`、`items`、`item_images`、`favorites`、`item_status_logs` | 谁在卖、卖什么、属于哪类、有哪些图、谁收藏了、状态怎么变 |
| 代取 | `runner_profiles`、`runner_item_sizes`、`errand_orders`、`errand_status_logs` | 谁可以接单、能接多大件、订单如何发布 / 接单 / 完成、状态怎么变 |
| 聊天 | `conversations`、`messages` | 谁和谁、因哪个商品或订单聊天、聊了什么、读没读 |
| 反馈 | `feedback` | 帮助页提交的意见 |

配套使用视图、存储过程、函数、触发器、事务、索引与约束，支撑商品列表聚合、代取大厅、未读数统计、防并发抢单、状态日志与冗余字段维护等场景；服务端用 `node-cron` 按在线计划自动切换跑腿上下线（数据库保持 0 个事件）。

## 未来展望

当前方案先解决「找得到、谈得成」，后续围绕交易安全、匹配效率、场景覆盖和运营能力四条线继续演进。

**交易更安全**

- **平台担保交易**：引入在线支付与资金托管，确认收货后再结算，配套退款与仲裁流程，取代目前聊天内自主转账的方式。
- **双向评价与信用体系**：交易和代取完成后互评，信用分、违约与差评记录对外可见，让靠谱的人更容易被选中。
- **风控与身份核验**：举报入口、违规商品下架、账号封禁，并逐步接入学生身份核验（校园卡 / 学籍信息），进一步收紧平台准入。
- **账号注销与恢复**：用户主动注销时只做软删除——昵称与联系方式匿名化，交易和聊天记录保留以备追溯，在售商品自动下架、待接单订单取消；学号在冷静期结束后释放，本人可在期限内申请恢复，避免一时冲动丢掉信用分与历史记录。

**匹配更聪明**

- **按真实位置排序**：获取用户定位，结合取送点计算距离，按「离我最近」排序代取订单与商品，在关键词、分类、价格筛选之外增加距离维度。
- **地图选点与路程预估**：发布订单时在地图上标注取送点，自动估算步行距离与耗时。
- **订阅与通知**：关注的商品降价、同类商品上新、顺路订单出现时主动推送，不必反复刷新。
- **全文检索与个性化推荐**：从关键词匹配升级到全文索引，结合浏览、收藏、成交行为排序，让首页越用越准。
- **AI 辅助**：拍照识别 ISBN 自动填充书目、根据成色与描述生成商品文案、给出价格参考区间，以及为跑腿订单评估顺路程度。

**场景更完整**

- **更丰富的沟通**：实时消息、语音消息、离线消息推送，逐步替代当前的三秒轮询。
- **搭子与招募板块**：约妆约拍、拼车、比赛招募、被试招募、社团招新，纳入统一的分类大厅与搜索。
- **求购与失物招领**：支持反向发布需求（我想收一本什么书）与失物招领，把校园里的零散需求也接进来。

**运营与规模化**

- **管理员后台**：内容审核、用户管理、订单仲裁与数据看板，支撑平台从「能用」走向「可运营」。
- **可持续的收入结构**：担保交易的少量服务费、校园广告位与增值服务。
- **多校区、多高校扩展**：按学校与校区做数据隔离，从一所学校跑通后复制到其他高校。
