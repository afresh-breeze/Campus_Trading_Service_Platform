# 校园服务APP项目方案总结

> 本方案是一款面向西南大学在校学生的垂直校园服务APP产品规划，核心解决当前校园二手交易、代取服务、搭子招募等场景信息分散、匹配效率低的痛点，采用「先核心后迭代」的开发路径，立足西大落地后逐步向外校扩张。

## 〇、课程设计版本边界（2026-11-30 前）

本文是产品规划，范围大于课程设计实际交付。课程设计以 `docs/课程设计开发计划.md` 和 `docs/A成员开发计划与Git协作手册.md` 为准：

- 实际交付 **20 个页面、14 张表**，覆盖登录注册、二手交易（含独立搜索结果页与书籍卡片）、代取（含找跑腿匹配、上线 / 接单设置）、聊天、个人中心（含设置 / 帮助）。
- **本次默认不做**：搭子 / 招募、平台担保交易、微信支付、管理员后台、实名认证、按真实定位距离排序；聊天收款码、WebSocket 实时通信、大模型 API 接入属于 P2 可选项，默认不排期，时间富余或老师明确要求时再评估。
- 本文中的“按定位距离排序”“学生认证”“聊天收款码”“搭子招募”等属于产品后续规划，写进报告“不足与展望”，不作为课程设计验收内容。
- 代取物品规格统一为 **小件 / 中件 / 大件，可多选**；跑腿接单模式分为两种：**按在线计划自动上下线**（单次具体日期或按星期循环）和 **现在上线（手动保持）**，不再设“长期”类型。
- 在线计划到点由服务端 `node-cron` 自动上下线；手动操作可临时覆盖，覆盖持续到下一个计划边界且最晚当天 23:59；数据库仍保持 0 个事件。
- 进行中的循环计划下线时询问“只提前结束这一次”还是“取消之后所有循环”；修改进行中的循环只影响下一次，前端弹窗提醒。
- 代取地点采用 **片区 + 具体地标** 两级：片区固定 25 个、用于匹配粗筛；教学区等再细分到 52 条具体楼栋、用于细筛；只选片区时细节写备注。

## 一、现存核心痛点

1. **渠道分散，沟通低效**：二手物品、代取、搭子等需求主要依赖校园频道、二手群，信息零散；用户为完成交易需添加大量好友，反复沟通成本高。
2. **曝光不稳定**：频道帖子易因浏览量低沉底，群聊消息易被新内容覆盖，供需双方匹配效率低。
3. **信息滞后**：物品是否售出、需求是否完成的状态更新不及时，无效咨询多。
4. **检索能力弱**：缺乏精准关键词搜索功能，找目标物品难度大；二手书籍交易需反复核对版本、ISBN、出版社等信息，流程繁琐。
5. **代取匹配慢**：代取服务无统一对接平台，供需匹配效率低。

## 二、产品定位与设计原则

- **定位**：聚焦高校校园场景的综合服务APP，以二手交易为核心，配套书籍专属专区、代取服务、搭子招募三大板块，兼顾使用便捷性与校内交易安全性。
- **迭代原则**：功能分为三类优先级——**黑色为基础核心功能、蓝色为扩展功能、红色为优化功能**，优先落地核心功能，再持续迭代更新。

## 三、核心功能架构

### 1. 二手交易模块（核心功能，含书籍专属专区）

**买家端**

- 搜索筛选：支持关键词全局搜索，搜索进入独立结果页；搜书时先展示书籍卡片（封面、书名、出版社、作者、ISBN），下方商品推荐同书优先；支持按校区、发布时间、价格等维度排序筛选（按真实定位距离排序列为后续规划）。
- 商品展示：列表展示卖家昵称、在售件数、商品名称、价格、新旧程度、赠品信息；书籍类额外展示书名、作者、出版社、ISBN。
- 详情与交互：商品详情页含图文描述、价格，支持收藏商品、一键发起聊天。
- 身份保障（产品后续规划）：校内学生认证，支持按学校、校区筛选；课程设计以演示账号登录替代，不做实名认证。

**卖家端**

- 专属卖书页：输入书名自动匹配已有书目并自动填充信息，无匹配项则手动填写ISBN、出版社等内容，补充价格、描述、图片后即可发布。
- 普通二手售卖页：填写商品名称、描述、价格、图片即可发布，支持设置是否可议价。

### 2. 代取服务模块（核心功能）

- **需求侧**：可发布代取订单，时间要求支持「尽快 / 截止时间 / 时间范围」；发布时先选片区、再选该片区下的具体地标（也可只选片区，细节写备注）；一键查询当前可接单的同学，按取件片区 + 具体地标、可接规格和时间重叠匹配；无合适匹配时，可将订单转至大厅公开招募。
- **供给侧**：支持「上线/下线」接单状态切换（个人页“接单设置”和代取页入口进入同一页，保留上次填写内容），可在大厅自主选单；个人页可多选服务片区和具体地标（地标可留空，表示整个片区都接）、设置按具体日期或按星期循环的在线计划、可承接物品规格（小件/中件/大件，可多选）、服务报价。计划到点自动上下线，也可“现在上线”或提前下线；未开始的计划可改/删，进行中的循环下线要选择只结束这一次还是取消之后所有循环。
- **订单管理**：跑腿接单后订单立即锁单，从大厅消失，不能被其他人重复接单；发布者或接单者都可以退回待接单，让订单重新回大厅；只有发布者可以确认完成；发布者也可以在无人接单时取消订单。截止时间仅作参考，系统不因超时自动取消，是否继续由交易双方协商。

### 3. 搭子/招募模块（扩展功能，课程设计不实现）

聚合多元校园组队需求，下设约妆/约拍、拼车、比赛招募、被试招募、社团/组织招新 5 个子分类：

- **统一大厅**：支持按分类、发布时间、热度筛选，支持关键词精准搜索。
- **分类发布**：
  - 拼车：可选择日期、时段，填写行程描述，支持标注长期有效，可上传图片。
  - 约妆/约拍：填写服务描述、时段，上传相关图片即可发布。
  - 比赛/被试招募：填写招募岗位、需求描述，附相关说明图片。
  - 社团招新：选择所属学院/社团、星级分类，填写社团简介、招新群号，可上传宣传图。

### 4. 即时聊天模块（核心功能）

- 统一聊天入口与聊天列表，支持基础即时通讯；订单相关聊天会带上商品 / 订单上下文，方便围绕完成、取消等情况沟通。
- 聊天内发送收款码属于产品后续规划（P2 可选），课程设计默认不实现。

### 5. 个人中心模块

课程设计版本包含个人信息管理、我的发布、我的收藏、我的代取、接单设置、设置、帮助等入口；“我买到的订单”、位置设置等属于产品后续规划，不纳入本次验收。

## 四、运营与发展规划

1. **交易安全路径**
   - 初期：依靠同校身份信任基础，采用用户自主交易、聊天内发收款码的模式。
   - 成熟期：积累用户信任后，上线平台担保交易机制，保障交易安全。
2. **身份核验**：通过学生认证机制，确保平台使用者为该校在读学生，降低交易风险。
3. **扩张路径**：先深耕西南大学市场，积累用户规模与运营经验后，逐步拓展至其他高校。

## 五、盈利模式

1. **交易抽成**：平台担保交易上线后，对成交订单抽取少量佣金。
2. **广告收入**：开放校园相关广告位实现变现。
3. 后续可拓展更多校园增值服务盈利点。
