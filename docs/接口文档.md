## 0. 公共约定

### 0.1 请求地址与请求头

| 项目 | 约定 |
| --- | --- |
| 开发地址 | `http://127.0.0.1:3000` |
| 小程序地址 | `miniprogram/config.js` 的 `BASE_URL`，真机联调时改成电脑局域网 IP |
| 数据格式 | JSON，`Content-Type: application/json` |
| 字符编码 | UTF-8 |
| 鉴权头 | `Authorization: Bearer <token>` |
| token 有效期 | 7 天 |
| 图片访问 | 接口只返回相对路径（如 `/uploads/xxx.jpg`、`/demo/item-1.jpg`），前端用 `BASE_URL + 路径` 拼接；不要返回 `127.0.0.1` 绝对地址 |
| 静态目录 | `server/uploads/` 映射到 `/uploads`；演示图片目录 `/demo` 由 `app.js` 挂载 |

### 0.2 统一响应格式

成功：

```json
{
  "code": 0,
  "message": "ok",
  "data": {}
}
```

失败：

```json
{
  "code": 400,
  "message": "参数错误",
  "data": null
}
```

约定：

- `code` 为 `0` 表示成功；失败时 `code` 与 HTTP 状态码保持一致（400、401、403、404、409、413、500）。
- `message` 是给用户看的提示，前端可以直接 toast。
- `data` 成功时是业务数据；失败时固定为 `null`。
- 服务端不得把 SQL 报错、堆栈、数据库账号密码返回给前端。

### 0.3 分页约定

除特别说明外，列表接口统一使用：

| 参数 | 类型 | 必填 | 默认 | 说明 |
| --- | --- | --- | --- | --- |
| `page` | number | 否 | `1` | 页码，从 1 开始 |
| `pageSize` | number | 否 | `10` | 每页条数，最大 `50` |

统一返回：

```json
{
  "list": [],
  "total": 0,
  "page": 1,
  "pageSize": 10
}
```

聊天会话列表和消息列表的默认条数按第 6 章单独说明。

### 0.4 字段约定

| 项目 | 约定 |
| --- | --- |
| 命名 | 一律 camelCase，如 `itemId`、`sellerNickname` |
| 时间 | `YYYY-MM-DD HH:mm:ss` 字符串，时区 `+08:00`；数据库连接已配置 `dateStrings: true` |
| 金额 | number，保留两位小数，如 `18.00`；数据库连接已配置 `decimalNumbers: true` |
| ID | number，如 `itemId: 15` |
| 逻辑布尔 | 统一返回 `true` / `false`，如 `isOwner`、`isOnline`、`negotiable` |
| 计数 | number，如 `favoriteCount`、`unreadCount` |
| 图片字段 | 相对路径字符串；无图/无头像时为 `null`，前端用默认图兜底 |
| 可空字段 | 未填写时返回 `null`，不要返回字符串 `"null"` 或 `"undefined"` |
| 校区 | `users.campus`、`items.campus` 为多校区预留字段；MVP 不采集、不筛选、不展示，固定返回 `null` |

### 0.5 HTTP 状态码与错误提示

| HTTP | code | 使用场景 | 典型 message |
| --- | --- | --- | --- |
| 200 | 0 | 请求成功 | `ok` 或具体成功提示 |
| 400 | 400 | 参数缺失、格式错误、枚举值非法、时间组合非法 | `参数错误`、`报酬不能为负数` |
| 401 | 401 | 未带 token、token 过期、用户不存在 | `请先登录`、`登录已过期` |
| 403 | 403 | 已登录但无权限：非本人商品、非发布者、非接单者、非会话参与者、账号被禁用 | `无权操作` |
| 404 | 404 | 商品、订单、会话、用户不存在；接口不存在 | `商品不存在`、`接口不存在` |
| 409 | 409 | 状态冲突：重复接单、非法状态流转、重复学号 | `该订单已被接单`、`该学号已注册` |
| 413 | 413 | 上传文件超过 5MB | `图片不能超过 5MB` |
| 500 | 500 | 未捕获的服务器错误 | `服务器错误` |

### 0.6 鉴权与角色判断

- 除 `GET /api/health`、`POST /api/auth/register`、`POST /api/auth/login` 外，所有接口都需要登录。
- 需要登录的接口统一先经过鉴权中间件；token 无效返回 401，账号被禁用返回 403。
- 角色判断只在后端做，前端传的角色参数不能作为授权依据。
- 常见角色：
  - 商品卖家：`items.seller_id === 当前用户`。
  - 代取发布者：`errand_orders.publisher_id === 当前用户`。
  - 代取接单者：`errand_orders.runner_id === 当前用户`。
  - 会话参与者：当前用户等于 `conversations.user_a_id` 或 `user_b_id`。
- 权限不符返回 403；状态不符返回 409；两者都不满足时优先返回 403（先判断“是不是你”，再判断“能不能做”）。

## 2. 认证

### POST `/api/auth/register`

- 鉴权：否
- 负责人：A
- 实现状态：已实现
- 说明：学号、密码、昵称注册；注册成功直接返回 token，前端可自动登录。不采集校区。

请求体：

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `studentNo` | string | 是 | 学号，6-20 位数字 |
| `password` | string | 是 | 密码，6-20 位，不能包含空格 |
| `nickname` | string | 是 | 昵称，2-12 个字符 |

请求示例：

```json
{
  "studentNo": "2023001",
  "password": "123456",
  "nickname": "小明"
}
```

成功响应 `200`：

```json
{
  "code": 0,
  "message": "注册成功",
  "data": {
    "token": "eyJhbGciOiJIUzI1NiIs...",
    "userInfo": {
      "userId": 1,
      "studentNo": "2023001",
      "nickname": "小明",
      "avatarUrl": null,
      "campus": null,
      "college": null,
      "phone": null,
      "creditScore": 60,
      "status": "active",
      "createdAt": "2026-11-10 13:30:00"
    }
  }
}
```

> 注意：返回字段名是 `userInfo`，不是 `user`。B 的登录页、注册页目前按 `data.userInfo` 取值，保持这个字段名。

失败情况：

| HTTP | message | 触发条件 |
| --- | --- | --- |
| 400 | `学号、密码、昵称不能为空` | 三个字段有缺失或全是空白 |
| 400 | `学号应为 6-20 位数字` | 学号格式不对 |
| 400 | `密码需 6-20 位且不能包含空格` | 密码格式不对 |
| 400 | `昵称需 2-12 个字符` | 昵称长度不对 |
| 409 | `该学号已注册` | 学号已存在 |
| 500 | `服务器错误` | 数据库异常 |

补充：

- 旧前端如果继续传 `campus`，后端会忽略，不会报错；数据库里 `campus` 保持 `NULL`。
- 密码使用 bcrypt 哈希存储，接口不会返回 `passwordHash`。

### PUT `/api/conversations/:id/read`

- 鉴权：是
- 负责人：B
- 实现状态：已实现（B，11-11）
- 说明：标记已读。方法固定 `PUT`，不要按 B 手册旧稿写成 `POST`。

路径参数：

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `id` | number | 是 | 会话 ID |

请求体：

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `lastMessageId` | number | 否 | 标记到这条消息为止；省略则标记该会话全部未读消息 |

请求示例：

```json
{
  "lastMessageId": 88
}
```

成功响应 `200`：

```json
{
  "code": 0,
  "message": "ok",
  "data": {
    "unreadCount": 0
  }
}
```

规则：

- 只把“对方发来且 `message_id <= lastMessageId`”的消息置为已读，不改自己发的消息。
- 省略 `lastMessageId` 时，把该会话内所有对方发来的未读消息置为已读。
- 返回标记后的未读数，正常为 0。

失败情况：

| HTTP | message | 触发条件 |
| --- | --- | --- |
| 400 | `会话 ID 不合法` | `id` 不是正整数 |
| 400 | `lastMessageId 不合法` | 传了但不是正整数 |
| 401 | `请先登录` | 未登录 |
| 403 | `无权操作该会话` | 当前用户不是会话参与者 |
| 404 | `会话不存在` | 会话不存在 |
| 500 | `服务器错误` | 数据库异常 |
