### 文件存放规范（重要）

**代码不放入 `docs/`。** 仓库目录约定：

```
Campus_Trading_Service_Platform/
├─ docs/                       # 只放文档：手册、设计说明、开发日志、报告
├─ miniprogram/                # 小程序源码（本条目交付）
├─ server/                     # Node/Express 后端（A）
├─ database/                   # SQL 脚本（A）
├─ project.config.json         # 开发者工具工程配置
└─ README.md
```

`docs/` 下只允许 `.md` 文件。小程序源码必须放在仓库根 `miniprogram/`，否则开发者工具的
`miniprogramRoot` 会失效，且会污染文档目录的检索与评审。

### 本地提交命令

git commit -m "feat(mp): 新增公共层地基代码 v1（20 页注册/请求封装/登录注册页）"

### 口径修正清单（A 审查意见，共 14 处）

字段名、表结构、枚举三处不一致会导致前后端联调直接失败，逐条修正如下：

| # | 位置 | 原写法 | 修正为 | 依据 |
| --- | --- | --- | --- | --- |
| 1 | 11-09 表单字段 | `deliveryPlace` | `deliveryLocation` | `errand_orders.delivery_location` |
| 2 | 11-09 表单字段 | `pickupLocation` | 删除，并入 `remark` | `errand_orders` 无此列 |
| 3 | 11-09 表单字段 | `description` | `itemDesc` | `errand_orders.item_desc` |
| 4 | 4.5 发送消息接口 | `{content}` | `{content, msgType}` | `messages.msg_type` |
| 5 | 4.5 已读接口 | `conversation_members.last_read_id` | `messages.is_read` | `messages.is_read` |
| 6 | 6.7 大厅字段表 | `pickupLocation` / `deliveryPlace` | 删除 / `deliveryLocation` | 同 1、2 |
| 7 | 6.8 发布页校验表 | `pickupLocation` input | `remark`（楼栋门牌） | 同 2 |
| 8 | 6.8 发布页校验表 | `description` textarea | `itemDesc` | 同 3 |
| 9 | 7.1 负责边界 | `conversation_members` | 无此表，成员关系在 `conversations.user_a_id / user_b_id` | A 的 14 表设计 |
| 10 | 7.x `assertMember` | `WHERE conversation_id = ? AND user_id = ?` | `WHERE conversation_id = ? AND (user_a_id = ? OR user_b_id = ?)` | 同 9 |
| 11 | 7.x 会话总数 | `COUNT(*) FROM conversation_members` | `COUNT(*) FROM conversations WHERE user_a_id = ? OR user_b_id = ?` | 同 9 |
| 12 | 7.x 标记已读 | `UPDATE conversation_members SET last_read_id` | `UPDATE messages SET is_read = 1 WHERE conversation_id = ? AND sender_id <> ?` | 同 5 |
| 13 | 9.x 答辩口径 | 「`fn_unread_count` 按 `last_read_id` 统计」 | 「按 `messages.is_read = 0 且 sender_id <> 我` 统计」 | 同 5 |
| 14 | 附录 关系模式 | 16 张表（含 `conversation_members`） | 14 张表，字段全量对齐 | 必须与 `database/schema.sql` 一致 |

**附带澄清（A 未提但同样影响联调）**

- 校区枚举只有 **南区 / 北区** 两个值，原稿的四校区写法（东/西/南/北）作废。
- `runner_profiles` 的字段是 `service_areas`、`service_places`、`time_slots`、`availability_type`、
  `manual_until`，原稿的 `zones` / `places` / `sizes` 写法作废；规格落在 `runner_item_sizes` 联合表。
- `items` 表保留 `description` 列，只有 `errand_orders` 用 `item_desc`，两者不要混。
