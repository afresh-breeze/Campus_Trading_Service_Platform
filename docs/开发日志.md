### 接口契约（前端已固化）

| 项 | 约定 |
| --- | --- |
| 响应体 | `{ code, message, data }`，`code === 0` 为成功 |
| 认证 | 请求头 `Authorization: Bearer <token>` |
| 字段命名 | camelCase |
| 分页 | 入参 `page` / `pageSize`，返回 `{ list, total, page, pageSize }` |
| 401 | 清本地登录态 → `reLaunch` 到登录页 |
| 超时 | 12000 ms |

路由分组：`/api/auth`、`/api/users`、`/api/items`、`/api/books`、`/api/favorites`、`/api/errands`、`/api/conversations`、`/api/upload`、`/api/feedback`、`/api/health`。

### 文件存放规范（重要）

**代码不放入 `docs/`。** 仓库目录约定：

```
Campus_Trading_Service_Platform/
├─ docs/                       # 只放文档：手册、设计说明、开发日志、报告
├─ miniprogram/                # 小程序源码（本条目交付）
├─ server/                     # Node/Express 后端（A）
├─ database/                   # SQL 脚本（A）
├─ project.config.json         # 开发者工具工程配置
└─ README.md
```

`docs/` 下只允许 `.md` 文件。小程序源码必须放在仓库根 `miniprogram/`，否则开发者工具的
`miniprogramRoot` 会失效，且会污染文档目录的检索与评审。

### 本地提交命令

在仓库根目录执行（代码包解压后覆盖到根目录）：

```bash
git checkout dev
git pull origin dev

# 将地基代码包中的 miniprogram/ 与 project.config.json 复制到本仓库根目录
# macOS / Linux 解压后：
#   cp -R <解压目录>/Campus_Trading_Service_Platform/miniprogram ./
#   cp <解压目录>/Campus_Trading_Service_Platform/project.config.json ./

git add miniprogram project.config.json
git status                     # 确认只新增了 miniprogram/ 与 project.config.json
git commit -m "feat(mp): 新增公共层地基代码 v1（20 页注册/请求封装/登录注册页）"
git push origin dev
```

## 变更记录格式约定

后续每个版本追加一节，包含四部分：

1. **交付范围**：新增/修改的文件与模块
2. **验证记录**：静态校验、编译结果、联调结果
3. **影响面**：是否影响接口契约、是否影响他人文件
4. **下一步**：下一批任务

提交信息前缀统一：`feat(mp):` 小程序功能、`feat(server):` 后端功能、`docs:` 文档、
`fix:` 缺陷修复、`chore:` 配置杂项。表结构与接口契约的变更必须在提交信息正文中显式标注。
