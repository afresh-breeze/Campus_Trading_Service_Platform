## 二、口径备注（不是 bug，但要写进报告）

1. **报酬上限两层口径**：后端/契约层 `MAX_REWARD = 99999999.99`（`DECIMAL(10,2)` + `CHECK reward>=0`），**前端收紧到 0 < r ≤ 200**。填 9999 时前端就拦，到不了后端——报告里写「前端收紧」而不是「后端拦截」。
2. **401 双语义**：登录「学号或密码错误」也是 401——`request.js` 用 `skipAuthRedirect` 区分：登录接口的 401 只 toast 不清会话，其余 401 才踢回登录页（避免输错密码被当成登录过期）。
3. **500 的文案来源**：业务校验失败（400/403/409）透出后端 `message`；真正的 500 由 A 的错误中间件统一为「服务器错误」——两端配合才做到「可读但不泄内部」。
